АФИНА 2.2 · КАТАЛОГ ОБЪЯВЛЕНИЙ И ЧЕРНОВИК БАННЕРА

РАБОТАЕТ
Вкладка «Объявления · Каталог» читает объявления выбранных кампаний.
ID кампаний можно вставить через пробел/запятую/новую строку; при первом
открытии подставляются кампании из уже загруженного отчёта Direct.
Перед чтением каталог подтверждает кабинет тем же снимком токена,
который используется затем для всех страниц каталога.
Методы только чтения: Ads.get, AdImages.get, Creatives.get.
Частично прочитанный каталог не выдаётся за полный.
Неизвестные типы — только просмотр. PreviewUrl/OriginalUrl/ThumbnailUrl
могут отсутствовать. Внешнее превью открывается в браузере только кнопкой,
а изображения не скачиваются автоматически и токен превью не передаётся.

ПОДГОТОВКА ЗАМЕНЫ
Выберите объявление и существующее изображение. Укажите путь к новому
PNG/JPEG. «Подготовить черновик замены» создаёт только локальный план:
- кабинет/кампания/группа/объявление;
- текущие хэши и выбранный слот, остальные изображения сохраняются;
- имя нового файла, размер, формат заголовка и SHA256;
- явный статус DRAFT_NOT_SENT, sentToYandex=false.
План можно сохранить в JSON. Это НЕ отправка и НЕ изменение объявления.
PNG/JPEG проверяется пока только по заголовку, не полным декодированием.
Совместимость с требованиями Яндекса и качество баннера не подтверждены.

Пока можно подготовить локальный план для TEXT_AD, IMAGE_AD с подтипом
TEXT_IMAGE_AD, RESPONSIVE_AD (замена одного выбранного изображения).
HTML5/CreativeId, другие типы и неоднозначная структура — только просмотр.
Товарные объявления и универсальные варианты записи не реализованы.

ЧТО НЕ РЕАЛИЗОВАНО
В программе НЕТ AdImages.add, Ads.update и других вызовов изменения.
Она не загружает баннеры, не запускает модерацию, не меняет бюджеты,
ставки, состояние, тексты или ссылки объявлений.
Для следующего этапа нужны:
1. Полная проверка изображения и требований типа/подтипа объявления.
2. Повторное чтение объявления и проверка, что исходные хэши не изменились.
3. Проверка SHA256 локального файла перед загрузкой.
4. Просмотр пользователем точной замены и подтверждение.
5. Отдельно проверенные upload/update, обработка результатов по каждому
   объекту, предупреждение о возможной модерации, контроль фактического результата.

БЕЗОПАСНАЯ ПРОВЕРКА
python desktop.py --demo
Демо-каталог синтетический. Реальные токены и API не используются.
229 offline-тестов пройдены. Рабочий интерфейс Windows и живой каталог
ещё не проверены. Разворачивайте рядом с рабочей версией, не поверх неё.
